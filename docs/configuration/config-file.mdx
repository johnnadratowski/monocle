---
title: "Config File"
description: "Customize monocle's layout, diff style, and behavior with a JSON config file."
---

Monocle loads settings from JSON config files at startup. You can maintain a global config for personal preferences and a project config for repository-specific settings.

<Note>
  Config is read once when the background engine (`monocle serve`) starts, not
  each time the TUI launches. Because the engine is long-lived and shared across
  TUI sessions, editing a config file and relaunching `monocle` alone will not
  pick up the change. To apply config changes, run `monocle stop` and then start
  `monocle` again — this restarts the engine and reloads the config.
</Note>

## File locations

Monocle loads config files in this order, with the project config taking precedence over the global one:

1. **Global:** `~/.config/monocle/config.json` (or `$XDG_CONFIG_HOME/monocle/config.json`)
2. **Project:** `.monocle/config.json` in your working directory

Create either or both files — you only need to include the settings you want to override.

## Example config

```json
{
  "layout": "auto",
  "diff_style": "unified",
  "sidebar_style": "flat",
  "theme": "dark",
  "wrap": false,
  "tab_size": 4,
  "context_lines": 3,
  "full_file_diff": false,
  "editor": "",
  "editor_mode": "terminal",
  "editor_focus": true,
  "markdown_viewer": "",
  "media_viewer": "",
  "walkthrough_on_stop": "",
  "walkthrough_view_status": "",
  "walkthrough_layout_reset": "",
  "walkthrough_navigate": "",
  "walkthrough_ask": "",
  "walkthrough_resolve": "",
  "related_editor_args": [],
  "ignore_patterns": [],
  "keybindings": {},
  "mouse": true,
  "min_diff_width": 80,
  "auto_focus_mode": false,
  "comment_expand": true,
  "comment_expand_delay": 2000,
  "review_tracking": true,
  "mark_reviewed_on_submit": "all",
  "idle_timeout": "30m",
  "review_format": {
    "include_snippets": true,
    "max_snippet_lines": 10,
    "include_summary": true
  }
}
```

## Settings

| Setting | Values | Default | Description |
|---------|--------|---------|-------------|
| `layout` | `"auto"`, `"side-by-side"`, `"stacked"` | `"auto"` | Pane arrangement (`auto` switches based on terminal width) |
| `diff_style` | `"unified"`, `"split"`, `"file"` | `"unified"` | Diff display mode (`file` shows raw content) |
| `sidebar_style` | `"flat"`, `"tree"`, `"grouped"` | `"flat"` | File list display mode (grouped = files grouped by category) |
| `theme` | `"dark"`, `"light"`, `"molokai"`, `"dracula"`, `"nord"` | `"dark"` | Color scheme for the TUI. `molokai`, `dracula`, and `nord` are true-color themes. Switch live with the `:theme <name>` command (or `:theme` to cycle); the choice is saved back to config. |
| `wrap` | `true`, `false` | `false` | Word-wrap long lines in diffs |
| `tab_size` | integer | `4` | Spaces per tab character |
| `context_lines` | integer | `3` | Unchanged lines shown around diff hunks |
| `full_file_diff` | `true`, `false` | `false` | Show the whole file with diff coloring instead of compact hunks (toggle with `a`) |
| `editor` | string | `""` | External editor command (overrides `$VISUAL`/`$EDITOR`); may include flags, e.g. `"code --wait"` |
| `editor_mode` | `"terminal"`, `"tmux_vertical"`, `"tmux_horizontal"`, `"tmux_window"` | `"terminal"` | How `Ctrl+g`/`Ctrl+o` open a file: `terminal` takes over Monocle's screen; the `tmux_*` modes (when running inside tmux) open the editor in a side-by-side split, a stacked split, or a new tmux window/tab. tmux modes fall back to `terminal` outside tmux. `Ctrl+Shift+g`/`Ctrl+Shift+o` always use `terminal`. |
| `editor_focus` | `true`, `false` | `true` | Whether a new tmux split/window takes focus (the `tmux_*` modes). Set `false` to keep focus on Monocle. |
| `markdown_viewer` | string | `""` | Rendered-markdown viewer launched by `Ctrl+p` for the current text artifact or `.md` file. May include flags and quoted arguments (e.g. `open -a "Google Chrome"` on macOS, or `glow -p`). Empty falls back to [`glow -p`](https://github.com/charmbracelet/glow) (its scrollable pager). |
| `media_viewer` | string | `""` | Viewer launched by `Ctrl+p` for media artifacts and image/video/audio files. May include flags and quoted arguments (e.g. `open -a "Google Chrome"`). Empty falls back to Google Chrome for the current OS. |
| `walkthrough_on_stop` | string | `""` | Shell command run on every [guided-tour](/guides/guided-tours) stop you settle on — how a stop's screenshots, recordings and window layout get shown. Run with `sh -c` in the repo root, in the background, with a 30-second timeout; a failure shows in the status bar. Its environment carries `MONOCLE_STOP_ID`, `MONOCLE_REPO_ROOT` and `MONOCLE_STOP_JSON` (the stop as JSON, view targets resolved to absolute paths). `:view N` runs it too, with `MONOCLE_VIEW_INDEX` and `MONOCLE_VIEW_NAME` naming the one view asked for. Empty runs nothing. |
| `walkthrough_view_status` | string | `""` | Shell command that says how the windows around the current [tour](/guides/guided-tours#which-views-are-showing) stop stand, so each view's label is marked open, hidden or not opened. Run like `walkthrough_on_stop` — same environment, `sh -c` in the repo root — but with a 500 ms timeout, when a stop is shown and after a view is opened. It prints one line of JSON such as `{"views": {"view": "open", "view2": "hidden"}, "layout": "default"}`. Empty, or a failure, shows nothing. |
| `walkthrough_layout_reset` | string | `""` | Shell command that puts the windows around a [tour](/guides/guided-tours#which-views-are-showing) back in their default layout. When `walkthrough_view_status` says `"layout": "saved"`, the tour note shows `layout saved · reset` flush right on the view's row; clicking `reset`, or typing `:layout reset`, runs it with `sh -c` in the repo root, with the same environment as the status command and a 10-second timeout, then asks the view status again. A failure shows in the status bar. Empty runs nothing. |
| `walkthrough_navigate` | string | `""` | Shell command that takes over when `ctrl+h/j/k/l` reaches the edge of Monocle's panes, in place of `tmux select-pane`. Runs with `sh -c`, with `MONOCLE_NAV_DIR` (`left`, `down`, `up` or `right`) and `TMUX_PANE` set, and moves focus itself, e.g. to a tour's windows beside Monocle. If it fails, the key goes to tmux as before. Empty hands every edge to tmux. |
| `walkthrough_ask` | string | `""` | Shell command that hands the agent the lines you send with `@`: the selection and the tagged lines, else the cursor's line. Runs with `sh -c` in the repo root and a 10-second timeout, with `MONOCLE_REPO_ROOT` and `MONOCLE_ASK_JSON` set — `{"tour": "…", "stop": "2.2", "repo": "/abs/repo", "refs": [{"path": "src/a.ts", "start": 312, "end": 316, "side": "new"}]}`. Adjacent lines of a file are merged into one range; `side` is `"old"` for removed lines, numbered in the old file; `tour` and `stop` are empty outside tour mode. It puts the reference in the agent's prompt and moves focus there. A failure shows in the status bar. Empty sends nothing. |
| `walkthrough_resolve` | string | `""` | Shell command that says what the lines you point at with `ctrl+]` reference — the SQL file a query loads, the file a function lives in. Runs with `sh -c` in the repo root and a 10-second timeout, with `MONOCLE_REPO_ROOT` and `MONOCLE_RESOLVE_JSON` set (the same shape as `MONOCLE_ASK_JSON` under `walkthrough_ask`), and prints a JSON array such as `[{"path": "db/queries/find_by_email.sql", "line": 12}]` — paths repo-relative or absolute, `line` optional. monocle opens those in the [related-files pane](/guides/guided-tours#related-files) beside the files it already holds, skipping ones already open, at most 8 files in all, and moves focus there. Printing nothing means nothing to open; a failure shows in the status bar. Empty opens nothing. |
| `related_editor_args` | string[] | `[]` | Extra arguments appended to the editor command of a [tour](/guides/guided-tours#related-files) stop's related-files pane, e.g. `["-S", "/path/setup.vim"]`. With vim and nvim, `+cmd`, `-c` and `-S` share a limit of ten (the pane uses one `-c` of its own) and `--cmd` has ten of its own; arguments that would go past either are left out, and the status bar says so. |
| `ignore_patterns` | string array | `[]` | Glob patterns for files to exclude |
| `min_diff_width` | integer | `80` | Minimum character width for the diff viewer in side-by-side layout |
| `mouse` | `true`, `false` | `true` | Enable mouse interactions (click, scroll, drag), including clicking a tour stop's views |
| `auto_focus_mode` | `true`, `false` | `false` | Auto-enter focus mode (hide sidebar, enable wrap) when reviewing plans |
| `comment_expand` | `true`, `false` | `true` | Auto-expand comments when the cursor hovers over them |
| `comment_expand_delay` | integer (ms) | `2000` | Delay in milliseconds before a comment auto-expands on hover |
| `review_tracking` | `true`, `false` | `true` | Enable review state tracking, snapshots, and change detection between rounds. Set to `false` for raw diffs with no reviewed indicators. |
| `mark_reviewed_on_submit` | `"all"`, `"commented"`, `"manual"` | `"all"` | Which files to mark as reviewed when submitting (requires `review_tracking`, see [Review State](/concepts/review-state)) |
| `idle_timeout` | duration string (e.g. `"30m"`, `"1h"`) | `"30m"` | How long `monocle serve` stays alive after the last client disconnects (plus a 60s grace window). Overridden by the `--idle-timeout` flag. Use `"0s"` or a negative value to disable. |
| `keybindings` | object | `{}` | Custom key overrides (see [Keybindings](/configuration/keybindings)) |
| `review_format.include_snippets` | `true`, `false` | `true` | Include code snippets in formatted reviews |
| `review_format.max_snippet_lines` | integer | `10` | Truncate snippets longer than this |
| `review_format.include_summary` | `true`, `false` | `true` | Include comment count summary in formatted reviews |

<Note>
  Toggle keybindings (`T`, `t`, `a`, `w`, `f`) change settings for the current session only. Edit the config file to persist your preferences.
</Note>
